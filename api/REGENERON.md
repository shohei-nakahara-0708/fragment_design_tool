# Regeneron フラグメント制作

画面: `/regeneron-fragments`（サイドバーの「リジェネロン フラグメント制作」）。

申請書1行につき1枚のカードを作成します。メール件名、フラグメント名、Linked Document、バナー画像、PDFページ別出力、ZIPダウンロードのみを中心にした画面です。参加登録URLは申請書のハイパーリンクから引き継ぎ、必要な場合だけ折りたたみ欄から修正できます。タスク・担当者・承認・Vault登録の管理は含みません。

## 起動設定

1. `api/venv/bin/pip install -r api/requirements.txt` で依存を更新します。
2. APIの環境変数に、event-manager と同じGmailの `GMAIL_TOKEN_JSON`、または `GMAIL_TOKEN_FILE` を設定します。認証形式はGoogleのauthorized-user JSON、権限は `gmail.readonly` です。JSON本文をリポジトリに保存しないでください。
3. 既存の `DATABASE_URL`、`SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`、`SUPABASE_BUCKET` をそのまま利用します。API再起動時に独立した `regeneron_cards`、`regeneron_messages`、`regeneron_settings` テーブルを作成し、画像とPDFを既存Storageの `regeneron/` 配下に保存します。
4. APIを再起動し、UIをビルド・起動します。ローカルの `api/.env` には既存Gmail認証ファイルの参照と今回の取込開始日時を設定済みです。本番の環境変数は別途設定します。

UIの `VITE_API_BASE` は、この変更を反映したAPIを指定してください。ローカル開発では空にしてViteのプロキシを使うか、`http://localhost:8000` を指定できます。既存の設定が本番APIを指している場合、ローカルUIにも本番APIのデプロイが必要です。

| 変数 | デフォルト・用途 |
| --- | --- |
| `REGENERON_GMAIL_ENABLED` | `1`。`0`で自動・手動取込を停止 |
| `REGENERON_GMAIL_INTERVAL_SECONDS` | `60`、最小30秒 |
| `REGENERON_GMAIL_QUERY` | `from:regeneron@ar40.jp`。旧実装と同じ受信対象 |
| `REGENERON_GMAIL_START_AT` | 未指定の場合は連携の初回起動日時。指定する場合は `2026-09-24T10:00:00+09:00` のようにタイムゾーン必須 |
| `REGENERON_TRANSCRIPT_SHEET_ID` | `1M1j_cJehL8Po7VHWr2gjXWen5AAUj6-Rh9aebYpzqtk`。申請書の転記先（gid=0 のシート） |
| `REGENERON_CHAT_WEBHOOK_URL` | 転記後に通知する Google Chat スペースの Incoming Webhook URL。未設定なら通知なし |

取込開始日時はDBへ初回のみ保存され、再起動しても変わりません。開始日時より前のメール・event-manager内の既存制作データは移しません。[Gmailの日時検索仕様](https://developers.google.com/workspace/gmail/api/guides/filtering)に合わせて検索にはepoch秒を使い、実際の受信日時も照合します。メールの未読状態は変更しません。

## デプロイ時の切り替え

ローカルと本番は同じDB・同じGmailを使います。二重取込・二重転記はDBで防いでいますが、先に拾った側のコードで処理されるため、取り込みを行うのは本番だけにします。

UIをローカルだけで使う間は、本番APIでは画面用API（`/regeneron/...`）を公開せず、メール取込・転記・Chat通知だけを動かします。

| 環境変数 | 本番API | ローカルAPI |
| --- | --- | --- |
| `REGENERON_GMAIL_ENABLED` | `1`（取込・転記・通知を行う） | `0` |
| `REGENERON_API_ENABLED` | `0`（画面用APIを公開しない） | `1`（未設定でも可） |

DBは共通なので、本番が取り込んだカードをローカルの画面で確認・編集できます。

1. 本番の環境変数に `GMAIL_TOKEN_JSON`、`GSA_JSON`（シート書き込み用、転記先シートの編集権限が必要）、`REGENERON_CHAT_WEBHOOK_URL` を設定します。Webhookが未設定だと、転記は行いますがChat通知（異常通知を含む）は送られません。
2. 本番をデプロイし、起動を確認します。
3. ローカルの `api/.env` を `REGENERON_GMAIL_ENABLED="0"` にしてローカルAPIを再起動します。ローカルでは自動・手動の取り込み、シート転記、Chat通知（未送信分の再送を含む）がすべて止まります。画面の閲覧・編集・ZIPダウンロードは使えます。

## アクセス制限（IP）

`/regeneron/...` のAPIだけを、許可したIPからのアクセスに限定できます。画面はAPIからデータを取るため、許可外のIPでは画面を開いても何も表示されません。ほかのツールや、裏で動くメール取込・転記・Chat通知には影響しません。

1. 本番APIで `https://<API>/regeneron/client-ip` を自分のPCから開き、`headers` のうち自分のIPが入っている項目を確認します（制限の対象外のURLです）。
2. 環境変数 `REGENERON_CLIENT_IP_HEADER` にそのヘッダーを設定します。`X-Forwarded-For` のように複数並ぶ場合は、プロキシが末尾に付ける値を使うため `x-forwarded-for:-1` のように位置も指定します（先頭の値は利用者が偽装できます）。
3. `REGENERON_ALLOWED_IPS` に許可するIPをカンマ区切りで設定します（`203.0.113.5,198.51.100.0/24` のように範囲も可）。未設定なら制限なしです。
4. もう一度 `/regeneron/client-ip` を開き、`detected` が自分のIPになっていることを確認します。

`REGENERON_CLIENT_IP_HEADER` が未設定のまま許可リストだけ設定すると、プロキシ経由では全員が拒否されます（安全側）。

## 取込・出力のルール

- 申請書はファイル名（「申請書」「フラグメント」を含む）か、Excelの中身（「講演会フラグメント申請」シートか申請書の見出し）で判定します。`.xlsx`・`.xlsm`に対応し、旧式`.xls`や壊れた申請書はエラーを表示して処理済みにしません。`.xlsx`で保存し直してください。
- 同一メールIDは一度だけ処理。同じスレッドの同じ講演会ID・ドキュメント名は同じカードを更新します。講演会IDがない場合はフラグメント名で突合します。異なるスレッドや識別項目が変わった依頼は別カードです。
- 申請書なし・PDFのみのメールは、既存スレッドのカードの画像を更新します。既存カードがなければ件名を使って1枚作成します。対象添付のない返信はカードを作りません。
- PDFが1つなら自動選択。複数の場合は申請書のドキュメント名・文書番号・講演会IDから一意に特定できるPDFを選び、不明な場合はカード上で選択します。
- UIで保存した項目・差し替えたバナーは次のメールで上書きしません。取込失敗は画面に表示し、次回の確認で再試行します。
- 件名に「新規依頼」「修正依頼」「フラグメント申請」を含む新規メール（返信・転送・取り消し通知を除く）で、そのメールにも同じスレッドにも申請書がない場合は、Chatに「申請書が添付されていない申請メールがあります」と1回通知します。
- 次の異常はChatにも通知します（同じ内容は1回だけ）。
  - 申請書の中身の問題で取り込めないメール（区分①が想定外、`.xls`、壊れたファイルなど）: メールごとに1回
  - メール取り込みそのものが3回連続で失敗（Gmail認証切れ・DB停止など）: 止まっている間は1日1回
  - 同じ申請のシート転記が3回連続で失敗（共有設定・空き行不足など）: 申請ごとに1回
- 取込・転記の失敗は、画面の「取り込まずに閉じる」で表示を消せます。そのメールは処理済みとして扱い、以後は取込も転記・通知も再試行しません。
- 区分①は「MKT（CSCC）」のような補足付き（申請書v4.1）でも読みます。カードのフラグメント名は MKT / Sales で作り、シートには申請書の値をそのまま（括弧は全角にそろえて）入れます。シートの区分①のプルダウン（Sales / MKT（NSCLC）/ MKT（CSCC）/ MKT（Cervical））にない値（旧申請書の「MKT」など）は赤字にし、Chat通知で選び直すよう知らせます。日付は「12/15/2026」（月/日/年）の表記も読みます。
- バナーは幅1200pxのPNG。PDFは全ページをページごとに保存し、編集画面のサムネイルから選んだページ（複数可、ページ順に banner・banner2…）だけをプレビュー・ZIPに使います。既定は1ページ目で、新しいPDFに差し替えると1ページ目に戻ります。
- PDFのページ内テキストに「地図」「案内図」「アクセスマップ」「MAP」などがあるページは「地図あり」と表示します。文字のない画像だけの地図は検知できません。この判定は今回の変更以降に変換したPDFが対象です。
- ZIPは `<フラグメント名>.html` と `images.zip`。内側は `images/banner.png`、`images/banner2.png`…、参加登録URLがある場合は `images/btn.png` です。
- 申請書にURLらしいラベルがあるのにリンクを解釈できない場合は、URLを修正するまでZIP出力を止めます。最初からURL欄が空ならボタンなしで出力できます。
- 1ファイル25MB、PDFは30ページまで。申請書やPDFがZIPの中に添付されている場合の展開は対象外です。

## スプレッドシート転記・Chat通知

- 申請書付きのメールを取り込むと、申請書の行を転記先シートのB列の最終行の次から書き込みます。書き込むのは B〜D・F〜V・AB〜AC のみで、関数列（E・W〜Z）と A（清算）・AA（memo）は触りません。
- B: 受領日（JST）、C: 件名に「修正」を含むか既存カードの再申請なら「修正」、それ以外は「新規」、D: 「申請内容確認中」、F: 区分①、G: 区分②（講演会/学会共催セミナー）、AB: 差出人の署名から取った姓＋様（取れない場合は英語名＋様）、AC: メール件名。
- 講演会IDがすでにシートのH列にある場合は「修正」とします（件名が【新規依頼】や別スレッドでも判定できるように）。
- 申請書は3行目付近の見出しから列を探すので、旧レイアウト（承認日なし）・v4.0（区分②がNSCLC/CSCC/Cervical）・v4.1が混在しても読めます。「例」の行は読み飛ばします。v4.0は区分①と区分②を合わせて「MKT（NSCLC）」などにします。
- 開催日は `2026年 12月 16日(水) 19:00-19:45` のような表記でも `2026/12/16` で入れます（0埋めなし）。時間は申請書の表記のまま（`~`・`～` もそのまま）入れ、先頭の日付だけ削除し、`/` で並んだ複数枠は改行にします。
- 文書番号の国コードが抜けている場合（`P.LIB.26.09.0006` など）は `JP.` を補い、赤字・通知の対象にします。承認日が申請書にない場合は、Chat通知で入力を促しU列を赤字にします。
- 日付・時間・URL以外の項目は、改行を半角スペースに置き換えます。講演会名は、先頭・末尾にある日付（`20260929_`、`260613_`、`2026年9月29日`、`9/29` など）と区切り文字を削除します。
- ドキュメント名は、末尾の括弧付きバージョン表記（`(v0.1)`、`（Ver.1.0）` など）を削除します。括弧なしの `Ver.2`・`_v2` は文書の版として残します。
- 元の値から変えたセルは文字色を赤にし、Chat通知に「変更前 → 変更後」を記載します。
- カードのフラグメント名（ZIP名）も同じ整形後の講演会名で作ります。導入前に取り込んだカードはAPI起動時に1回だけ作り直します（画面で手動編集したものは対象外）。
- 転記はメール取込と同じトランザクションでキュー（`regeneron_exports`）に登録し、失敗時は次回同期で再試行します。シート転記済みでChat通知だけ失敗した場合は通知のみ再送します。PDFのみのメールは転記しません。
- サービスアカウントに転記先シートの編集権限が必要です。シートの関数入り行が足りない場合はエラーを表示して転記を止めます。

## 確認

```sh
api/venv/bin/python -m unittest discover -s api/tests -p 'test_regeneron*.py' -v
cd ui
npm run build
npx eslint src/pages/RegeneronFragmentsPage.jsx
```

テストは合成の申請書・PDFを使用し、Gmail・本番DB・Storageへ接続しません。Repositoryの競合処理テストにはSQLiteアダプタを使用するため、本番PostgreSQLへの接続確認はデプロイ時に別途必要です。
